## 1. 星星兑换：扣分时机与退款规则

### 已确认决策

采用预扣模式。

孩子提交兑换申请时，系统直接扣减 `User.points_balance`。家长审批通过后，兑换进入“待兑现”；家长确认兑现后，兑换完成。家长拒绝申请时，系统自动退回预扣余额，并写入一条 `refund` 类型的 `PointsLog`。

兑换状态机：

```text
申请（余额预扣） -> 待审批 -> 已批准（待兑现） -> 已兑现
                         \-> 已拒绝（退款）
```

免审批额度内的兑换跳过“待审批”，直接进入“待兑现”。MVP 的有效免审批额度为：

```text
max(家庭全局免审批额度, 孩子当前等级免审批额度)
```

### 工程实施约束

- 免审批额度使用等级折扣后的实际支付星星数进行判断。
- MVP 不使用奖励级别的独立免审批阈值；相关历史字段在实现前从数据模型中移除或标记为保留字段。
- 创建兑换、校验库存、校验余额、预扣余额、写入兑换记录和写入积分流水必须位于同一数据库事务。
- 每次兑换请求必须携带客户端幂等键。家庭范围内的幂等键必须唯一。
- 退款事务必须以 `redemption_id` 和 `refund` 类型建立唯一约束，确保一次兑换最多成功退款一次。
- 退款仅恢复 `points_balance`，不增加 `points_earned_total`。
- 已兑现记录进入终态。已拒绝记录在退款成功后进入终态。
- 库存品在申请成功时预占库存；拒绝或申请事务失败时释放库存；兑现后将预占转为消耗。

## 2. 星星余额：存储位置与防重复

### 已确认决策

`User` 表直接存储以下字段：

- `points_balance`：当前可消费余额。
- `points_earned_total`：历史累计获得积分，用于等级计算。
- `version`：乐观锁版本号。

积分发放以 `checkin_id` 为幂等键，同一打卡仅发放一次。兑换扣分和退款使用乐观锁，更新时携带读取到的 `version`；版本冲突时重新读取并重试。

所有积分变动写入 `PointsLog`，至少包含：

- `type`：`earn`、`redeem`、`refund`、`manual`。
- `business_type` 和 `business_id`：关联业务类型与业务主键。
- `delta`：有符号变动值。
- `balance_before` 和 `balance_after`：变动前后余额。
- `created_at`：服务端记账时间。

### 工程实施约束

- 余额字段和积分流水必须在同一数据库事务中更新。
- 乐观锁更新采用 `WHERE id = ? AND version = ?`，成功时令 `version = version + 1`。
- 单次业务操作最多自动重试 3 次；持续冲突时返回可重试错误，不产生部分流水。
- `PointsLog` 对 `(type, business_type, business_id, user_id)` 建立唯一约束。
- `earn` 和正向 `manual` 同时增加 `points_balance` 与 `points_earned_total`。
- `redeem` 仅减少 `points_balance`；`refund` 仅恢复 `points_balance`。
- 负向 `manual` 仅减少 `points_balance`。扣减后的余额下限为 0。
- 等级由 `points_earned_total` 派生。缓存的当前等级必须在同一积分事务内同步更新。
- 对账任务以 `PointsLog` 重算余额并报告差异；修复差异必须通过审计型 `manual` 流水完成。

## 3. 预设任务类型：复制到家庭

### 已确认决策

系统使用“全局模板，创建家庭时复制”的方式管理预设任务类型。

`task_type_templates` 存储 5 种系统模板：

- `study`
- `sport`
- `chore`
- `habit`
- `custom`

系统模板不属于具体家庭。创建家庭时，系统将 5 条模板复制到该家庭的私有 `task_types`。家长修改名称或图标仅影响当前家庭。

系统增加预设类型时，需同时更新模板数据，并通过迁移脚本补写到已有家庭。

### 工程实施约束

- `task_type_templates.code` 全局唯一。
- `task_types` 对 `(family_id, template_code)` 建立唯一约束，保证家庭初始化与迁移可重复执行。
- 家庭创建和预设类型复制必须位于同一数据库事务。
- 家庭私有记录保存 `template_code` 作为来源标识；名称、图标和启用状态均允许家庭覆盖。
- 模板后续更新不覆盖家庭已经修改的名称和图标。

## 4. 协作任务：周期与孩子提交状态

### 已确认决策

每个协作任务周期创建一条 `CollaborationRound`：

```text
CollaborationRound:
  id, task_id, round_number, start_date, end_date,
  status(pending/active/completed)
```

每个参与孩子在该周期下独立提交：

```text
CollaborationSubmission:
  id, round_id, child_id, submitted_at,
  content(JSON: text + MediaAttachment[]),
  verified_by(parent_id), verified_at,
  status(pending/approved/rejected)
```

当期所有分配孩子均已提交且全部通过后，系统统一发放积分。任一孩子尚未提交或被打回时，该周期保持未完成状态。

### 工程实施约束

- 创建周期时必须保存参与者快照，避免任务后续改派影响历史周期。
- 新增 `CollaborationRoundParticipant`，至少包含 `round_id`、`child_id`、奖励积分快照和参与状态。
- `(round_id, child_id)` 在参与者表和提交表中均建立唯一约束。
- 被拒绝的孩子可在当前周期重新提交；重新提交后状态回到 `pending`，并保留审核历史。
- 周期完成判断仅基于参与者快照，要求所有有效参与者的最新提交状态均为 `approved`。
- 周期完成、状态更新、完成事件写入和全部参与者积分发放必须组成一个幂等事务流程。
- 积分插件使用 `(round_id, child_id)` 作为协作奖励业务键，每名参与者按周期创建时的奖励积分快照获得积分。
- 周期生成器对 `(task_id, round_number)` 建立唯一约束，重复调度不会产生重复周期。

## 5. 孩子 PIN：加密、锁定与重置

### 已确认决策

| 规则项 | 决策 |
|---|---|
| 加密算法 | bcrypt，与家长密码使用同一密码学方案 |
| PIN 长度 | 4-6 位纯数字 |
| 输错锁定 | 连续 5 次错误后锁定 15 分钟，前端显示倒计时 |
| 锁定范围 | 按 `child_id` 锁定，不影响其他孩子 |
| PIN 重置 | 家长在“家庭成员 -> 编辑孩子”中重置 |
| 密码模式 | 最少 6 位且必须包含字母；孩子可在“我的信息”中修改 |

### 工程实施约束

- 数据库仅存储 bcrypt 哈希值，不保存 PIN 或密码明文。
- bcrypt cost 由服务端配置管理，MVP 默认值为 12。
- 登录失败计数、锁定截止时间和服务端当前时间共同决定锁定状态。
- 登录成功后清零当前孩子的连续失败计数。
- 锁定状态下的登录请求返回统一认证错误和剩余锁定秒数，不执行密码哈希比较。
- 家长重置 PIN 或孩子修改密码后，系统撤销该孩子已有会话和刷新令牌。
- 登录接口按家庭、孩子和客户端地址实施速率限制；审计日志记录成功、失败、锁定和重置事件，且不记录凭据内容。
- 前端倒计时仅用于展示，服务端锁定截止时间是授权判断依据。

## 6. 照片、视频与语音：统一数据结构

### 已确认决策

```typescript
type MediaType = 'image' | 'video' | 'audio';

type MediaAttachment = {
  id: string;
  type: MediaType;
  url: string;
  thumbnail_url?: string;
  duration?: number;
  size_bytes: number;
  width?: number;
  height?: number;
  created_at: string;
};
```

统一媒体结构用于：

- `CheckIn.media`
- `GrowthRecord.media`
- `Reward.image`
- `User.avatar`
- `BadgeTemplate.icon`

媒体统一存储到腾讯云对象存储 COS。上传流程包含前端压缩与分片、后端文件类型及大小校验。本决策覆盖 v5 PRD 中关于 Cloudflare R2 / S3 的原始建议。

### 工程实施约束

- API 返回 `MediaAttachment`；数据库使用独立 `MediaAsset` 记录，并通过关联表表达业务归属和展示顺序。
- `MediaAsset` 额外保存 `object_key`、`mime_type`、`checksum`、`upload_status` 和 `deleted_at`。
- `url` 由服务端根据 `object_key` 生成；数据库不依赖临时签名 URL 作为资源标识。
- COS Bucket、Region 和访问域名由家庭创建者在管理后台配置，并按 `family_id` 存入数据库。
- COS Bucket 使用私有读写权限；客户端通过后端授权获取短期上传凭证或预签名请求。
- COS 永久访问凭据以加密密文存入数据库，仅在服务端内存中按请求解密，不进入浏览器代码、日志、文档或仓库。
- 上传状态使用 `pending`、`uploading`、`ready`、`failed`；业务提交仅可引用 `ready` 媒体。
- 后端必须校验声明 MIME、文件签名、大小、数量、时长以及当前家庭对媒体的所有权。
- 分片上传使用 `upload_id` 和分片序号保证重试幂等，完成后校验 checksum。
- 成长记录引用原媒体对象并创建独立业务关联，避免复制 COS 对象。
- 删除业务记录时先解除业务关联；无引用媒体由异步清理任务执行软删除和对象回收。

## 7. MVP 插件架构范围

### 已确认决策

| 层级 | MVP 范围 | 说明 |
|---|---|---|
| EventBus | 完整实现 | 发布/订阅和命名空间隔离 |
| PluginRegistry | 搭建骨架 | manifest 声明元信息、依赖和权限；提供 `register()`、`unregister()` |
| 模块目录 | 独立开发 | 打卡、积分、等级、奖励、成长记录使用独立目录 |
| 模块开关 | 界面留位 | MVP 全量加载模块 |
| 动态加载 | Phase 2 | 使用 `import()` 按需加载，并支持禁用模块不加载代码 |

MVP 的架构目标是骨架完整、模块解耦、开关留位、静态加载。

### 工程实施约束

- MVP 使用编译期静态插件清单，应用启动时统一注册插件。
- 插件之间仅通过公开契约、应用服务或命名事件通信，不导入其他插件的内部模块。
- manifest 至少包含名称、版本、公开能力、依赖、订阅事件和发布事件。
- EventBus 事件名称采用 `<module>.<entity>.<event>.v<version>` 格式。
- 事件载荷必须包含 `event_id`、`occurred_at`、`family_id`、`actor_id` 和 `correlation_id`。
- 同一数据库事务内的跨模块事件使用 Outbox 记录；事务提交后由事件分发器投递，消费者按 `event_id` 幂等处理。
- MVP 设置页中的模块开关明确标记为后续能力，开关不改变运行时加载状态。
- `unregister()` 在 MVP 用于测试和应用关闭清理，不承诺运行时热卸载。

## 8. 通知系统与 PWA 开发阶段

### 已确认决策

| 功能 | 阶段 | 范围 |
|---|---|---|
| 核心业务事件 | Phase 1 | 为后续通知消费提供稳定事件契约 |
| 通知系统 | Phase 2 / V1.1 | 站内通知中心、浏览器推送、三层偏好开关 |

Phase 1 聚焦家庭、任务、打卡、积分、等级和奖励兑换核心闭环。Phase 4 的重复 PWA 条目已经清理。

### 工程实施约束

- Phase 1 定义通知所需的领域事件，不实现通知中心、Push Subscription、Service Worker 或离线队列。
- Phase 1 页面中的通知入口使用“即将推出”状态，不展示虚构通知数据。
- Phase 2 使用服务端注册的动作标识处理通知快捷操作，不在通知数据中保存可任意调用的 API 地址。
- PWA 离线打卡必须在 Stage 2 单独定义本地队列、冲突处理、媒体续传和幂等规则。

## 9. 跨模块一致性规则

以下规则属于 MVP 的统一工程基线：

1. 所有业务表携带 `family_id`，服务端从认证上下文确定家庭边界。
2. 客户端提交的 `family_id` 仅用于一致性校验，不能覆盖认证上下文。
3. 所有金额、星星和积分字段使用整数。
4. 所有服务端时间以 UTC 存储，界面按家庭时区展示。
5. 所有状态迁移由领域服务执行，API 层不直接更新状态字段。
6. 余额、库存、积分流水和兑换状态的关联变更使用数据库事务。
7. 外部副作用通过 Outbox 驱动，数据库事务内不直接执行网络调用。
8. 所有关键写操作记录操作者、关联家庭、业务键、请求关联 ID 和服务端时间。
9. 软删除记录保留审计信息，默认查询过滤已删除数据。
10. 数据库唯一约束承担最终幂等保护，应用层幂等检查用于快速返回已有结果。

## 12. 开发阶段访问地址

### 已确认决策

FamilyStar 项目域名当前待定。开发阶段通过服务器公网 IP 和开发容器端口访问：

```text
http://119.29.111.248:8098
```

生产容器保留 `8099` 端口，生产访问地址在域名和 HTTPS 方案确认后启用。

### 工程实施约束

- 开发容器将前端服务绑定到 `0.0.0.0:8098`。
- 浏览器统一访问前端入口，前端通过同源 `/api` 反向代理请求内部 Hono API。
- 数据库、Redis、API 和 Worker 仅通过 Docker 内部网络通信，不直接暴露公网端口。
- 开发环境的公开基础地址通过环境变量配置为 `http://119.29.111.248:8098`，代码中不硬编码服务器地址。
- 开发环境 CORS 允许来源精确匹配公开基础地址。
- 开发环境会话 Cookie 使用 `HttpOnly` 和 `SameSite=Lax`；当前 HTTP 访问阶段使用 `Secure=false`。
- 生产环境启用 HTTPS 后，会话 Cookie 使用 `Secure=true`，并通过生产环境变量配置正式域名和允许来源。
- OAuth 回调、媒体回调和其他绝对 URL 统一从环境变量中的公开基础地址派生。

## 13. 家庭级邮件与 COS 配置

### 已确认决策

每个家庭在家长管理后台维护独立的邮件服务和腾讯云 COS 配置。家庭创建者拥有新增、修改、测试和删除权限；共同管理者仅查看配置状态和最近验证结果。

邮件配置至少包含：

- SMTP Host、Port、TLS 模式。
- 发件人名称和发件人地址。
- SMTP 用户名和密码或授权码。

COS 配置至少包含：

- Bucket、Region、访问域名。
- SecretId 和 SecretKey。

### 数据模型

`FamilyIntegrationSetting` 按 `(family_id, integration_type)` 唯一，`integration_type` 支持 `email` 和 `cos`。记录至少包含：

- 非敏感配置 JSON。
- 加密后的凭证载荷。
- 加密后的数据密钥及对应 nonce、认证标签。
- 主密钥版本。
- 配置状态、最近验证时间、最近验证结果。
- 创建者、更新者和 UTC 时间戳。

### 加密规则

- 每条凭证记录生成独立的 256 位数据加密密钥。
- 凭证载荷使用 AES-256-GCM、独立随机 nonce 和认证标签加密。
- 数据加密密钥由服务器环境变量中的主密钥包裹后存入数据库。
- 主密钥仅存在于服务器环境变量或后续密钥管理服务中，数据库和仓库不保存主密钥。
- 记录保存 `key_version`，支持主密钥轮换和后台批量重包裹数据密钥。
- 服务启动时校验主密钥长度与格式；配置缺失或无效时，凭证保险库进入不可用状态并阻止凭证读写。

### 接口与权限规则

- 创建、修改、测试和删除接口仅允许当前家庭创建者调用。
- 共同管理者只能读取配置是否完成、掩码标识、最近验证时间和验证状态。
- API 响应不返回 SMTP 密码、授权码、COS SecretId、COS SecretKey、密文或加密元数据。
- 更新请求中的空凭证字段保留原凭证；凭证轮换使用明确的替换操作。
- 邮件测试向家庭创建者地址发送测试邮件。
- COS 测试在家庭专属探测目录执行上传、读取和删除，并记录脱敏后的结果。
- 解密后的凭证只在单次服务调用内存在，错误和审计日志只记录集成类型、家庭、操作者、结果和错误分类。
- 家庭缺少有效邮件配置时，邀请流程提供可复制的邀请链接，并提示创建者完成邮件配置。
- 家庭缺少有效 COS 配置时，媒体上传入口显示“需要配置对象存储”，文字和勾选打卡继续可用。

## 14. 家长密码、会话期限与家庭时区

### 已确认决策

| 规则项 | 决策 |
|---|---|
| 家长密码 | 至少 12 个字符，不强制字符类型组合 |
| 登录会话 | 家长和孩子均采用滚动 30 天有效期 |
| 家庭时区 | 注册时读取浏览器 IANA 时区，读取失败时使用 `Asia/Shanghai` |

### 工程实施约束

- 服务端验证家长密码长度，密码仅以 bcrypt cost 12 哈希形式持久化。
- 每次通过认证的请求将当前会话到期时间更新为服务端当前时间后 30 天。
- 家长或孩子凭据发生变更时，系统撤销对应主体的全部现有会话和刷新令牌。
- 注册接口接受浏览器提供的 IANA 时区标识；服务端验证标识有效性，并对缺失或无效值使用 `Asia/Shanghai`。
- 服务端继续使用 UTC 存储时间，界面和家庭日历规则按家庭时区计算及展示。
