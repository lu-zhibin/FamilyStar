# 家庭总览与徽章领域

## 家庭总览

`GET /api/v1/family/dashboard?date=YYYY-MM-DD` 仅供家长会话读取。接口从会话取得家庭 ID，以家庭 IANA 时区校验业务日期并返回：

- 每名活动孩子的应做任务数、已完成数、待审核数和当日所得积分。
- 待审核提交、待审批兑换和待兑现兑换计数及目标页面。
- 最多三十条按服务端发生时间和稳定 ID 倒序排列的近期动态。

近期动态直接读取打卡、协作提交、审核、积分、等级、兑换、愿望、成员、邀请和徽章颁发业务记录。Outbox 仅承担事件投递，不作为总览业务状态来源。

## 徽章模型

徽章领域包含 `BadgeTemplate`、`BadgeAward` 和 `BadgeProgress`：

- 模板保存家庭、展示字段、受控条件、颁发级别、可见性、启用状态和版本。
- 颁发保存模板展示快照、孩子、颁发人、原因、来源事件和服务端颁发时间。
- 进度按模板、孩子和级别唯一保存当前值、目标值和评估时间。

受控条件包括任务完成次数、连续天数、累计积分、等级、协作次数和手动颁发。新家庭初始化首个任务、累计七次任务、连续七天、累计一百分、达到三级和首次协作六个模板。

## 颁发一致性

Worker 消费积分变化、等级提升和协作完成事件，重新计算当前孩子的全部启用自动模板。`(template_id, child_id, level)` 唯一键保证事件重投不会重复颁发。

自动和手动颁发均在同一事务写入 `badges.award.created.v1` Outbox 事件。颁发 ID 同时作为事件 ID，使颁发记录与事件保持一一对应。

已有颁发记录的模板保留展示快照。条件或颁发级别修改会返回冲突，系统预设和已有颁发记录的模板受到删除保护。

属性回归覆盖五种自动条件在阈值前、等于阈值和阈值后的判定，以及同一事件重复投递时颁发记录与 Outbox 事件均只创建一次。模板后续修改不会改变历史颁发名称、说明、图标、分类、条件和版本快照。

## API

- `GET /api/v1/family/badge-templates`
- `POST /api/v1/family/badge-templates`
- `PATCH /api/v1/family/badge-templates/:templateId`
- `DELETE /api/v1/family/badge-templates/:templateId`
- `POST /api/v1/family/badge-awards`
- `GET /api/v1/badges/me`

所有仓储查询和写入都包含认证家庭 ID。孩子徽章墙身份固定来自当前孩子会话。

## 双端界面

家长端 `/badges` 展示预设与自定义模板，支持创建、编辑、启停、自定义模板受保护删除，以及向家庭孩子手动颁发启用的手动徽章。写入期间锁定重复操作；冲突后刷新服务端权威模板状态。

孩子端 `/child/achievements` 读取本人徽章墙。已获得项使用颁发时的名称、图标和描述快照并展示原因与时间；未获得自动徽章展示实时当前值、目标值和可访问进度条，未获得手动徽章显示等待家长颁发。
